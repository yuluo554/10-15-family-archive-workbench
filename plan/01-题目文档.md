# 10-15 老照片/家庭档案数字化整理工作台（模拟项目题）

> **性质**：不参赛 · 发布 GitHub 公开仓库 · 署名 yuluo554 · 系列标准形态（PySide6 桌面 exe + CLI 双形态）
> **目标产出**：仓库 `10-15-family-archive-workbench`，纯本地单机，零上传
> **版本史**：v1 · 2026-10-14 定稿
> **定位宣言**：现有照片工具都围着"有 EXIF 的现代照片 + 自动识别"转，而家庭档案的主食恰是无 EXIF 的扫描件、家书、证件——本工具以**人工元数据编目**为核心、按档案著录标准建字段体系、纯本地单机，可复现的**著录规则校验与版本化字段方案**是聊天给不了的。

## 一、介绍

**痛点**：
- 家庭照片/文献数字化的产物大多是"一堆无元数据的扫描件"：老照片翻拍、家书、户口簿/证件扫描页，没有 EXIF、没有时间线、没有人物关系，散落各处。
- 主流照片管理工具（Immich / PhotoPrism / digiKam / Google Photos）的检索主线是"EXIF 时间 + 地点 + 自动识别人脸/场景"，对**无 EXIF 的混合媒体扫描件**基本失能：要么聚成一堆"未分类"，要么强行跑识别但家庭老照片识别准确率低且涉及上传云端的隐私风险。
- 档案行业的著录标准（DCMI、GB/T 11821 的照片号与文字说明规则）解决了"字段该怎么定"，却没有面向家庭的轻量落地工具。

**开源空白**（软论据，检索基准日 2026-10-14，检索式见 data/README.md）：
- Immich（~116k★）/ PhotoPrism（~40k★）：重服务端部署，围绕现代照片自动识别；
- digiKam：桌面端，但主线仍是自动识别 + EXIF 驱动；
- elodie（~1.5k★）：完全依赖 EXIF，无 EXIF 即瘫痪；
- may3rr/dingying（~1★）：偏照片修复，非编目。
- "无 EXIF 混合档案 + 人工编目 + 纯本地桌面"三要素同时成立的中文工具近乎为零——这是本项目的立足点。

**为什么是工具而不是 AI 聊天**：编目数据的**持久化状态**（档案库 + 字段版本史）、**可复现的著录规则校验**（必填集/受控词表/W3CDTF 日期格式，逐条可回溯到标准出处）、**可程序化验证的基准**（合成样例带真值）——这三件事聊天会话给不了，必须靠软件与数据文件。

## 二、任务要求（首期 5 个模块，其余留扩展）

> 每个模块遵守确定性纪律：**凡引用标准条文或外部素材的规则，未挂原文核对（✅）不得落库/生效/进入计算路径**；核对状态与依据记入 data/README.md。

### 模块 1：档案项导入（混合媒体类型）
- **输入**：本地文件夹/文件——照片扫描件（JPEG/TIFF/PNG）、翻拍照片、家书/文献扫描页、证件扫描页；可选读取现代照片的 EXIF（仅作辅助字段预填，exiftool/pillow 解析，不依赖）。
- **输出**：档案项记录（条目 ID、媒体类型、文件指纹、缩略图、原始 EXIF 快照若有），写入本地档案库。
- **确定性纪律**：EXIF 仅作预填建议、永不自动写入著录字段；无 EXIF 文件走同一录入路径；文件指纹（SHA-256）保证同件不重复入库。

### 模块 2：DCMI-based 著录字段 profile 与录入表单（核心模块）
- **输入**：自建 DCMI profile（字段定义文件，JSON/YAML）：以 DCMI Metadata Terms 15 核心元素 + 选用 terms 为骨架，映射出面向家庭的字段（标题/人物/时间/地点/描述/类型/语言/权利…）；必填集、受控词表（如媒体类型取 DCMI Type 词汇）、W3CDTF 日期格式校验规则。
- **输出**：逐字段的录入表单 + 规则化校验器：必填缺失提示、词表外取值拦截、日期不符合 W3CDTF 格式拦截；校验规则逐条标注出处（DCMI spec 条目名），可参数化（profile 文件可编辑、可版本化）。
- **确定性纪律**：字段定义与校验规则以数据文件定义、一处定义多处引用；profile 文件带版本号，字段方案变更留版本史（versioned 字段方案——招牌模式，差异是真实的：可选字段集与必填集在不同 profile 版本间实质可区分，由项目自定，非冒充官方版本）。

### 模块 3：人物/代际关系标注与家庭年表生成
- **输入**：档案项的人物标注（姓名、称谓/代际、与档案项的关系）、人物间关系边（父子/夫妻/祖孙…）。
- **输出**：人物索引页（每人参与的档案项列表）、代际关系图（纯本地渲染）、按编目时间轴生成的家庭年表视图。
- **确定性纪律**：关系边类型取自受控词表；未编目完成的档案项不进入年表；人物合并去重（同名者由人工确认，不自动合并）。

### 模块 4：检索与导出（含敏感字段抹除的白名单导出）
- **输入**：字段/人物/时间范围/媒体类型的组合查询；导出请求（目标：JSON/CSV 档案包 + 原件副本）。
- **输出**：检索结果列表；按**导出字段白名单**生成的导出包——默认抹除 GPS、证件号类敏感字段（白名单以数据文件定义，可审）。
- **确定性纪律**：导出包内附 manifest（来源 profile 版本、白名单版本、导出时间）；抹除字段在导出文件中不出现而非置空。

### 模块 5：合成档案测试样例与内置基准
- **输入**：程序化生成器——生成带真值著录元数据的模拟扫描件样例集（人名用假名白名单，见 data/README.md），真值与植入字段同源生成。
- **输出**：样例集 + 真值清单（manifest）+ 校验断言（模块 2 校验器对样例的通过/拦截行为与真值一致；模块 4 白名单导出对敏感字段的抹除断言）。
- **确定性纪律**：真值从生成器单一来源输出，注记不手写第二份口径；基准覆盖度口径（按"必填校验/词表拦截/W3CDTF 拦截/敏感字段抹除/人物关系"各异常类型列最低覆盖项）写进 manifest。

### 扩展项（不入首期验收）
- **OCR / 人脸识别**：默认关闭、如启用必须纯本地模型、联网全 opt-in——因预检⑤（规则化程度弱）+ 隐私红线，降级为扩展（决策记录）。
- **EXIF 版本对照包**：EXIF 2.3 vs 3.0 版本差异素材已核（✅：3.0 新增 UTF-8 文本标签、清理废弃 tag、修订镜头 tag）；但 CIPA 规范 PDF 无法脚本直连获取（⬜，阻断原因见 data/README.md），**原文需手动下载落地后录入**，录入前不进入计算路径。

## 六、边界与非目标

- **不做**：AI 照片修复/上色/去划痕；云端同步或任何默认联网；自动 OCR/人脸识别（默认关闭，启用也仅纯本地，联网功能全 opt-in）。
- **隐私红线**：纯本地单机、零上传；导出默认抹除 GPS、证件号等敏感字段（白名单机制）；合成样例人物一律用假名白名单（"张三丰/李四"式登记名，见 data/README.md），禁止真实人名/真实证件号入样例。
- **免责定位**：本工具是家庭档案整理的辅助编目工具，不是档案鉴定/法律凭证工具；著录质量由使用者人工负责。
- **品牌隔离**：不复制任何既有照片管理工具代码；与本项目系列其他仓库互不提及对方业务、不共享代码。
- **首期范围限定**：仅上述 5 个模块，OCR/人脸/EXIF 对照包/DA/T 对齐均为扩展项；防 scope 失控。
- **数字纪律**：本文档不写会随实现漂移的硬数字（用例数/体积/通过率），指标口径与门槛来源写进 manifest，数值以末态回填；标准数值/条文引用以原文核对（✅）后入库。
