# plan/03 — 架构与模块设计

> 状态：✅ 初稿 · 2026-10-14 · 对应里程碑 M2/M3/M5
> 上游：plan/01-题目文档.md 模块 1–4；plan/02 数据底座设计

## 1. 总体架构：核心库 + 双前端

```
┌─────────────────────────────────────────────┐
│  前端 A：PySide6 桌面 GUI（录入表单/年表/检索）  │
│  前端 B：CLI（导入/校验/检索/导出/基准）        │
└──────────────────┬──────────────────────────┘
                   │
        ┌──────────▼──────────┐
        │   famarchive core    │   ← 全部业务逻辑在核心库，GUI 不含规则
        │  (profile 校验器/档案库│
        │   导入/关系/导出/基准) │
        └──────────┬──────────┘
                   │
   SQLite(纯本地) + profile/vocabularies(数据文件)
```

原则：
- **核心库无 GUI 依赖**：CLI 与 GUI 调同一函数，保证"录入→编目→年表→检索→导出全链路在 exe 内可达"且行为一致；
- **纯本地零上传**：核心库不引入任何网络客户端依赖；EXIF 解析用 pillow（可选依赖，缺失则跳过预填）；
- GUI 框架 PySide6 与打包工具 PyInstaller 仅作可选依赖组，CLI/基准测试不需要装它们。

## 2. 包结构（骨架已部署）


## 3. CLI 子命令（与模块一一对应）

| 子命令 | 对应模块 | 状态 |
|---|---|---|
| `famarchive import <path>` | 模块 1 导入 | M2 |
| `famarchive validate [--item ID]` | 模块 2 校验 | M3 |
| `famarchive persons / timeline` | 模块 3 人物与年表 | M3 |
| `famarchive search <query>` | 模块 4 检索 | M5 |
| `famarchive export <out> --whitelist ...` | 模块 4 导出 | M5 |
| `famarchive benchmark` | 模块 5 基准断言 | M4 |
| `famarchive profile show` | profile 版本查看 | 骨架已通 |

## 4. GUI 页面结构（M3/M5 实装）

1. 导入页：文件夹/文件拖入 → 指纹去重结果 → EXIF 预填建议（可采纳/放弃，永不自动写入）；
2. 编目页：逐字段表单（由 profile 驱动生成）+ 逐字段校验提示（挂规则出处）；
3. 人物页：人物索引 + 关系边编辑（词表下拉）+ 同名人工确认合并；
4. 年表页：按编目完成时间的家庭年表（未编目完成不进入）；
5. 检索页：字段/人物/时间/媒体类型组合查询；
6. 导出页：白名单选择 + 导出包预览（含 manifest 预览）。

## 5. 确定性纪律落点

| 纪律 | 代码落点 |
|---|---|
| EXIF 仅预填、永不自动写入 | `importer.py`：EXIF 结果只进 `prefill_suggestions`，写库走显式确认 |
| 无 EXIF 同一路径 | 导入流程对 EXIF 缺失不分支，预填为空列表 |
| 指纹去重 | `store.py`：SHA-256 唯一约束 |
| 未核对规则不进计算路径 | `profile.py`：`source` 字段缺失的规则加载即报错 |
| 抹除 = 不出现 | `exporter.py`：白名单外字段不序列化，非置空 |
| 假名白名单 | `benchmark.py` 生成器只从词表取人名 |

## 6. 依赖策略

- 运行必需：Python ≥3.10、PyYAML；
- 可选：pillow（EXIF/缩略图）、PySide6（GUI）、PyInstaller（打包）→ `pip install .[gui,pack]`；
- 打包 exe：profile/词表数据文件内嵌 + `resources.py` 定位，免安装可达，依赖内嵌。
